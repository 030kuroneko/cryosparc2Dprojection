Slurm runs under the service account. An administrator configures resources once; other users only select Slurm.

Administrator · Slurm setup

Use the private administrator key file shown in the server terminal. Never share this key with other users.

Enter the launcher administrator key to edit Slurm settings.Use the private key provided by the launcher administrator. This is separate from your CryoSPARC password.
Enter a dedicated directory accessible from the server and compute nodes.Use the same absolute path on all nodes, outside CryoSPARC-managed project folders. The directory must be owned by the service account with permissions 700. Local job history stays on this server.
Enter the Python executable available on compute nodes.Use an absolute path to the environment containing this package and its dependencies. The default is this server’s active Python; verify the same path works on compute nodes.
Leave blank for the cluster default, or enter your partition name.Selects the Slurm partition for new jobs. Use a partition available to the service account.
Leave blank for the cluster default, or enter your Slurm account.Sets the Slurm allocation or billing account for new jobs.
Leave blank for the cluster default, or enter an allowed QoS.Sets the Slurm quality-of-service policy for new jobs. Available values depend on your cluster configuration.
Request 4 CPUs per job by default.Enter a positive integer. More CPUs reserve more resources but may not accelerate every stage.
Use 1 to reserve a GPU for image-only search; 0 keeps CPU jobs.Choose a GPU partition and install compatible CuPy on the compute-node Python environment. The search uses one NVIDIA GPU.
Default: 16384 MiB (16 GiB) per job.Sets the Slurm memory request. Larger maps and full-grid surface extraction may need more memory.
Default: 120 minutes per job.Sets the maximum Slurm runtime. Allow enough time for searching and rendering; the scheduler may terminate jobs that exceed this limit.

Changes apply only to new jobs. Saving does not submit a job or verify compute-node connectivity.
